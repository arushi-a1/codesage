# API Reference

Base URL: `http://localhost:8000/api` (interactive docs at
`http://localhost:8000/docs`, generated by FastAPI from the same routes).

All endpoints except `/auth/register` and `/auth/login` require:

```
Authorization: Bearer <access_token>
```

## Auth

### `POST /auth/register`
```json
{ "email": "dev@example.com", "password": "supersecret1", "full_name": "Dev" }
```
→ `201` `UserOut`

### `POST /auth/login`
```json
{ "email": "dev@example.com", "password": "supersecret1" }
```
→ `200` `{ "access_token": "...", "refresh_token": "...", "token_type": "bearer" }`

### `POST /auth/refresh`
```json
{ "refresh_token": "..." }
```
→ `200` new `TokenPair`

## Repositories

### `POST /repositories`
Import and start indexing a repo. Indexing runs as a FastAPI background
task; poll `/repositories/{id}/status` or `/repositories/{id}` for progress.
```json
{ "github_url": "https://github.com/owner/repo", "branch": "main" }
```
→ `201` `RepositoryOut` (`status: "pending"`)

### `GET /repositories`
→ `200` list of `RepositoryOut` owned by the current user.

### `GET /repositories/{id}`
→ `200` `RepositoryOut`

### `GET /repositories/{id}/status`
Lightweight status/progress check backed by Redis (falls back to the DB
row if no live job status is cached).
→ `200` `{ "status": "embedding", "detail": "Embedding 812 chunks across 96 files" }`

### `POST /repositories/{id}/reindex`
Re-clones and re-indexes the repo (e.g. after new commits).
→ `200` `RepositoryOut`

### `DELETE /repositories/{id}`
Deletes the repo's Qdrant collection and Postgres records.
→ `204`

## Chat

### `POST /chat/sessions`
```json
{ "repository_id": "...", "mode": "chat", "title": "optional" }
```
`mode` ∈ `chat | codegen | bug_detection | architecture | refactor`
→ `201` `ChatSessionOut`

### `GET /chat/sessions/{session_id}/messages`
→ `200` list of `ChatMessageOut` (includes `citations`).

### `POST /chat/sessions/{session_id}/messages`
Streams the assistant's reply as **Server-Sent Events**
(`Content-Type: text/event-stream`). Persists the user message immediately
and the assistant message once the stream completes.

Request:
```json
{ "content": "How does authentication work in this repo?" }
```

Event stream (`data: <json>\n\n` per event):
```
data: {"type": "citations", "citations": [{"path": "app/api/deps.py", "start_line": 12, "end_line": 30, "symbol": "get_current_user"}]}

data: {"type": "token", "content": "Authentication "}

data: {"type": "token", "content": "uses JWT..."}

data: {"type": "done"}
```
On failure: `data: {"type": "error", "message": "..."}`.

Returns `409` if the repository isn't `ready` yet, `429` if the per-user
rate limit (default 30 requests/min) is exceeded.

## Pull request review

### `POST /repositories/{id}/pull-requests/{pr_number}/review`
Fetches the PR's diff + metadata from GitHub, runs it through the agent in
`pr_review` mode, and streams the review the same way chat does (same SSE
event shape, no `citations` event since there's no chat history to seed
from — the diff itself is the context).

Returns `502` if the GitHub API call fails, `409` if the repo isn't ready,
`429` on rate limit (default 10 requests/min — reviews are more expensive).

## Error shape

FastAPI's default HTTPException body:
```json
{ "detail": "human-readable message" }
```
